{% translate 'Agents write the code. The specification and the review are mine.' context 'how I work page' %}

{% blocktranslate trimmed %} I build software with AI agents in four steps: I write the specification, agents with different roles implement it, I review every plan and every change, and nothing reaches production without passing the tests and continuous integration. With this method I delivered the first five epics of a CRM, 19 stories, in two weeks, with more than 2,000 automated tests. {% endblocktranslate %}

  1. 01

    {% translate 'Specification' %}

    {% blocktranslate trimmed %} Before any code is written there is a brief, a phased scope and acceptance criteria. On larger projects that means a PRD, an architecture, epics and one spec per story. The specification lives in the repository next to the code, so whoever comes later, person or agent, knows what was decided and why. {% endblocktranslate %}

  2. 02

    {% translate 'Agents with roles' %}

    {% blocktranslate trimmed %} I work with Claude Code and the BMAD method. One agent plans, another implements and another reviews, each with its own instructions. I use subagents, custom commands, instruction files and MCP servers so each agent only has the context it needs. {% endblocktranslate %}

  3. 03

    {% translate 'Human review' %}

    {% blocktranslate trimmed %} I approve every plan before it runs and read every change before it is merged. Agents speed up writing the code; product and architecture decisions are not delegated. {% endblocktranslate %}

  4. 04

    {% translate 'Verification' %}

    {% blocktranslate trimmed %} Automated tests (pytest, Jest, Maestro), API contracts locked with OpenAPI and continuous integration on every change. If something fails, it is not merged. {% endblocktranslate %}

02 / {% translate 'Frequently asked questions' %}

{% translate 'What is spec-driven development?' %}

{% blocktranslate trimmed %} Writing down first what has to be built and how you will know it is right, and then building it. With AI agents, it is what turns a code generator into a predictable team: the agent works against the specification and the review checks against it. {% endblocktranslate %}

{% translate 'What is the BMAD method?' %}

{% blocktranslate trimmed %} An open-source method for AI agent-driven development that splits the work into roles (analyst, product, architecture, development, review) and produces documents that build on each other: brief, PRD, architecture, epics and stories. {% endblocktranslate %}

{% translate 'Is code written by agents reliable?' %}

{% blocktranslate trimmed %} As reliable as the review and the tests around it. That is why I review every change and nothing is merged without passing the tests and continuous integration. {% endblocktranslate %}

{% translate 'Can I use this method with my team?' %}

{% blocktranslate trimmed %} Yes. I offer training and hands-on support so your team can work with AI agents under specification and review, on your own projects. {% endblocktranslate %}
